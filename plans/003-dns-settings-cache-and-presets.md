# 003 — Add durable DNS policy, a cache switch, and hostname-only presets

Planned at `a35e3890ae00c5d9925f3fb9e40e3761ca149f7d`, 2026-10-14. Priority P1; effort L; risk MED; category feature/correctness. Status: IMPLEMENTED, pending review. Depends on 002 for shared native admission/deadline behavior. Direct transport execution follows in 005; do not release intermediate UI that claims it already works.

## User-approved behavior

- Keep the existing resolver choice as **Remote DNS**. Preserve every existing custom value.
- Add independently stored **Direct DNS**, initially System DNS, for bootstrap and explicitly configured bypass domains. IP/ASN-only rules continue using Remote DNS for unclassified names; excluded apps keep Android/network DNS.
- **Cache DNS responses** defaults to on, including for existing installations. Off means each accepted captured query performs its own upstream exchange: no positive/negative response reuse, no late-answer storage, and no concurrent-query coalescing. Connection pools and direct-routing metadata remain enabled.
- DoT and DoH presets contain only provider hostnames. Numeric IPs remain valid in custom configurations, ordinary UDP/TCP presets, resolver-protection routes, and actual socket addresses. HTTP/3 is a distinct transport and its existing numeric preset is unchanged in this release.

These are device-wide settings, not Hysteria profile fields and not additions to shared `hysteria2://` links. Bedlam can disable its own response caches; it cannot disable Android, browser, recursive-server, or other application's caches.

Network identity is runtime data, not a saved DB field. Use serialization defaults so omitted new cache fields mean enabled, not Go's zero-value false; test this explicitly. Keep DNS preferences out of profile export. Verify migration tests load a genuine schema-6 database and retain custom remote addresses, MTU, profiles and route sources. A fake repository is insufficient for migration verification.
3. **Complete UI/persistence plumbing.** Show Remote DNS and Direct DNS sections with the existing provider/transport/custom-entry controls and validation. Show one global response-cache switch with concise help text. Direct System uses the underlying network's DNS; it is not the existing Remote System filtering policy. Prevent saving invalid/empty custom selections rather than silently switching to Cloudflare. Keep existing valid custom IPs and URLs unchanged. Carry the new policy through the existing startup/settings-update APIs; this step does not require 004's coordinator yet. Cache and Remote behavior must work through those existing paths. Direct controls remain disabled with an implementation-status explanation until 005 makes them operational. Package 004 subsequently serializes these application paths, before Direct is enabled. Verify reducer/executor/repository round trips, fake repositories and Compose previews compile through `./gradlew testDebugUnitTest`.
4. **Make cache state generation-aware without restarting transport.** Use separate Direct and Remote namespaces; include resolver identity, relevant routing/resolver-policy generation and Direct network generation. Maintain a separate response-cache epoch: cache off/on increments that epoch, not the routing/network generation used by domain leases. Clearing/disabling/changing response policy retires outstanding singleflight work and normal/late stores: check the captured epoch under the same lock as storage. A request in the new epoch must not join old work. Cache off skips `tryCached`, both lookups, all stores and singleflight; retain parsing, response validation, transaction IDs, admission limits and pooled connections. Add a narrow live API, for example `HysteriaClient.setDnsCacheEnabled` → `Session.SetDNSCacheEnabled`, that does not call `updateTun`, `StopTUN` or rebuild upstreams. Cache-only app updates use that API even before 004 lands. Use one authoritative policy source so no UDP/TCP caller accidentally keeps caching. Verify delayed ordinary and late answers cannot repopulate disabled/retired caches, while the same transport objects remain in use.
5. **Correct cache lifetime and eligibility.** Remove the positive 5-second minimum. Never extend the upstream lifetime; TTL 0 is uncached, TTL 1/4 expires at the advertised time, and aged TTL fields saturate at zero. Preserve existing negative SOA limits. Treat request-specific/unsupported EDNS options conservatively: bypass both cache and coalescing unless their semantics are explicitly represented in the cache identity. The baseline key includes UDP size and DO/CD/RD but ignores EDNS option bytes, so ECS/Cookie requests must not share answers. Do not weaken DNS validation to accommodate the new switch. Verify fake-clock/bounded-time tests for each lifetime and EDNS case using existing DNS wire fixtures.
6. **Remove preset fallbacks.** `DnsTransport.Tls` becomes only the provider TLS hostname; `Https` only its URL. Leave `cloudflareAddresses`/`googleAddresses` intact for protection routes. Do not use Direct DNS to locally resolve Remote DoT/DoH hostnames; these still go through Hysteria and are resolved server-side. Preserve TLS hostname/SNI/HTTP authority. Verify `DnsPresetsTest`, `RoutePlannerTest`, `dns_tls_test.go`, `dns_https_test.go`, and custom-input tests. Broken server-side hostname resolution must yield an understandable failure, with no hidden numeric, System or Direct fallback.

## Acceptance tests

| Area | Required observation |
|---|---|
| Old installation | Cache on; old Remote choice/custom servers preserved; Direct System; old explicit MTU preserved |
| Cache on | Repeated normal query hits; negative cache ages; same-generation late answer can help |
| Cache off | Sequential and concurrent identical queries each reach upstream; TTL-bearing replies are not stored; TCP and UDP behave identically |
| Live off/on | Old normal/late completions never repopulate or join new-generation work; turning on begins empty |
| Isolation | Same name through Direct/Remote or two Direct network generations never shares responses |
| TTL/EDNS | 0/1/4-second TTLs; aged additional data; NXDOMAIN/NODATA; distinct ECS/Cookie values; ordinary EDNS/DO/CD regression |
| Presets | Exact hostname-only DoT/DoH lists; custom numeric resolvers untouched; numeric protection routes retained |
| Connection reuse | Cache off increases DNS exchanges without opening one new TLS/HTTP connection per request |
| Cache-only update | No TUN factory call or resolver-pool replacement; after 005, unexpired direct leases and existing direct TCP/UDP flows survive off/on without requiring another DNS query |

## Stop and maintenance

Stop if Room cannot migrate existing custom values losslessly, live policy change can mix generations, or hostname-only presets require disabling certificate checks. Do not delete the cache implementation or connection pooling. Response caching, transient request bookkeeping and Direct address-routing leases are separate concepts; new code and UI must keep their meanings distinct. All future DNS paths must honor the global cache switch and its generation rules.
