# 004 — Apply one routing policy consistently across network changes

Planned at `a35e3890ae00c5d9925f3fb9e40e3761ca149f7d`, 2026-10-14. Priority P1; effort L; risk MED; category correctness. Status: IMPLEMENTED, pending review. Depends on 003's explicit DNS/IPv6 policy model; complete before 005 uses network-bound Direct DNS.

## Findings addressed

1. **Network selection:** `app/src/main/kotlin/ru/shapovalov/bedlam/core/vpn/DefaultNetworkListener.kt:32–47,60` reports every available matching network as selected on Android 10/11, clears selection when any is lost, and shares validation state between networks. Direct DNS must not mix one network's resolver addresses with another network's sockets.
2. **Mixed route plans:** `BedlamVpnService.kt:362` writes `currentRoutePlan` before calling `updateTun`; the network path independently writes it at 498. `establishTun` reads that shared variable at 375. Native `updateTun` acquires its lock later (`hysteria/.../HysteriaClientImpl.kt:172`). Android Builder routes can therefore come from a different plan than native DNS/IPv6 settings.
3. **IPv6 policy collapse:** `core/routing/engine/RoutePlanner.kt:25` maps both Disabled and BypassOnly to false; native `tun.go:131` suppresses AAAA in either case. Planner lines 64/98 still exclude LAN/source IPv6 addresses even in Disabled mode; the legacy path subtracts them at 110. A claimed `::/0` alone is not proof that IPv6 cannot bypass.
4. **Deleted-source race:** `core/routing/domain/usecase/RefreshRouteSourcesUseCase.kt:29–34` and `AddRouteSourceUseCase.kt:16–18` commit asynchronous results after deletion. `data/local/RoutingDao.kt:59–63` inserts without checking the parent, whose FK is enforced by `ResolvedCidrEntity.kt:10`. This can throw instead of discarding an obsolete result.

## Scope and conventions

Allowed app files: `core/vpn/{DefaultNetworkListener,UnderlyingNetworkObserver,BedlamVpnService,NetworkChangeReset}.kt`, a small testable network selector and route-apply coordinator; routing model/engine/data/DAO/repository/use cases/worker and their focused tests; DI for those seams; database test dependencies only where real Room coverage requires them. Native changes: explicit IPv6 policy handling in `tun.go`, relevant API/config adapters and tests. Use existing Kotlin coroutine fakes under `app/src/test/kotlin/ru/shapovalov/bedlam/testing`, and table-driven Go tests. Do not refactor the entire VPN service, app navigation, notifications, imports or updates.

## Steps

1. **Test the races first.** Run `git diff --stat a35e389..HEAD -- app/src/main/kotlin/ru/shapovalov/bedlam/core hysteria`; reconcile 003. Introduce a controllable route-apply seam so tests can suspend before invoking the TUN factory. Write tests where network plan A and settings plan B overlap and assert the Builder/native pair always receives the same immutable snapshot. Write deletion-during-resolution tests using a real Room database. Run `./gradlew testDebugUnitTest`; newly added assertions must expose the intended failures before the fix.
2. **Publish an underlying-network snapshot.** Track per-network capabilities and link properties; ignore loss of a nonselected network. On API 31+, retain best-matching callback behavior. On API 29/30, select a usable non-VPN active network when identifiable; otherwise prefer validated candidates, retain a still-eligible selection to avoid flapping, then use a documented deterministic transport/tie policy. Test both arrival orders rather than depending on callback order. Use one dispatcher/synchronization policy. Include network identity, DNS server addresses and a monotonic generation; DNS changes on the same network must invalidate Direct pools/cache. Never strip private LAN resolvers from Direct System. Preserve existing filtering for Remote System. Verify selector unit tests and Android 10/11 device handoffs.
3. **Serialize and classify policy application.** One coordinator covers startup/settings/network policy application and publishes immutable desired/applied generations. A cache-flag-only change must call 003's cache-only API: no TUN replacement, pool reset, routing-generation change or direct-flow closure. A resolver/rule/network change uses an explicit native policy update that retires the affected resolver/lease generations; replace TUN only when Android routes, advertised DNS addresses, app filter, MTU or interface/IPv6 configuration actually require it. Compute this change classification from immutable snapshots and test it. When replacement is necessary, pass `plan` explicitly to `establishTun(plan, tunConfig)` through the operation's factory; it must not read a mutable global plan. Commit the applied snapshot only after success. A failed old operation cannot restore an older plan over a newer applied one; coalesce superseded desired updates, and cancel safely on disconnect. Coordinate with the native session lock rather than holding a lock across a callback that reacquires it. Verify interleaved success/failure/cancellation scenarios with fake `HysteriaClient` and factory recording. The narrow resolver/rule update becomes operational in 005; this package defines and tests its coordinator contract without enabling an unfinished Direct option.
4. **Preserve three IPv6 meanings.** Carry Enabled/Disabled/BypassOnly across the Kotlin/Go boundary. Disabled suppresses AAAA, refuses captured IPv6 data and removes nonessential IPv6 LAN/user/source exclusions so they cannot defeat the sink; preserve essential interface bookkeeping and the protected outer server connection, which may itself use IPv6. Enabled resolves A/AAAA using normal domain selection. BypassOnly keeps IPv6 outside the VPN and no longer synthesizes empty AAAA; 005 routes its AAAA lookup to Direct. Test effective membership, including exclusions and longest-prefix rules, for both API33+ and legacy route generation. Assert a disabled IPv6 server profile can still reach its protected IPv6 server.
5. **Make route-resolution commits conditional and atomic.** DAO transaction checks source existence and expected source revision/value before replacing CIDRs plus timestamp/error. Missing/deleted/replaced sources discard the result without resurrecting them. Include resolver/network generation for Direct domain refresh so old network answers cannot overwrite new ones. Use a consistent transactional configuration/source/resolution snapshot for plan building, replacing the current per-source read loop where touched. Rethrow coroutine cancellation; surface unexpected manual-refresh failures through store state/labels instead of an uncaught coroutine exception. Verify real Room FK/concurrent-delete tests and existing refresh/use-case tests.
6. **Retry actual transient refresh failures.** Have refresh return structured per-source outcomes; WorkManager currently returns success after the use case records network errors (`RouteRefreshWorker.kt:19–24`). Retry transient failures with bounded backoff, retain previous CIDRs on failure, avoid redoing successful fresh sources, and stop retrying invalid input. Preserve cancellation. This small additional improvement is recommended while changing this exact path. Verify all-success/mixed/transient/permanent/cancellation cases in worker-policy tests.
