Bedlam 1.5.3 fixes the connection drops that happen when the screen turns off. It also makes the log possible to send.

**The tunnel dropped when the phone slept**

- The phone suspends the CPU soon after the screen turns off. The keepalive timer stops with it. The server then gets no packets. It closes the session. Neither side tells the app.
- Bedlam now checks the tunnel when the device wakes. It also checks after two quiet minutes. Before, it checked only while an app sent data and got nothing back. If a tunnel died while no app used it, the app still showed it as connected.
- In a test, version 1.5.2 showed "Connected" for 4 minutes 28 seconds after the tunnel was gone. Version 1.5.3 finds the same fault in 62 seconds. It finds it at once if you turn the screen on.

**QUIC timers**

- The default idle timeout is now 120 seconds. The keepalive is 30 seconds. Version 1.5.2 used 30 and 15.
- QUIC uses the shorter of the client limit and the server limit. A 30-second client limit also caps the server. No server setting could keep a sleeping phone connected for longer.
- **Raise `quic.maxIdleTimeout` on your server to get this.** Against a standard server the limit stays 30 seconds.

**What this release does not fix**

- Some phones stop Bedlam completely when the screen is off. Xiaomi, Oppo, Vivo and Huawei do this. A stopped app cannot start itself again.
- Turn on always-on VPN in Android settings. The system then starts the service again. This is the only method that recovers a stopped app.
- Settings, Keep VPN alive lists the other settings to change.

**The log can now leave the phone**

- The log screen has a Share action. It writes the visible lines to a file. The file starts with the app version, the phone model and the Android version.
- Long lines now wrap. Before, a screenshot cut off the end of a long message.
- The log keeps 5000 lines. It kept 1000. The screen shows a note when it drops older lines.

**The Session screen showed an address with no tunnel**

- The screen looked up your address in every connection state. With the VPN off, it showed your real address. The caption said that the address came through the tunnel.
- The lookup now needs a live tunnel. With the tunnel down, the screen tells you so.

**Other changes**

- The phone vibrates one time when the tunnel comes up.
- A numeric profile field that you do not set showed `0`. The screen now says what the `0` means.
- The MTU field showed an empty box in automatic mode. It now shows the MTU in effect.
- The connection timer uses a clock that a clock correction cannot move.
- The connect button stops its animation after a few seconds.
- Settings has an About section with the version, the licence and the source link.
- The Hysteria core moved from 2.12.0 to 2.12.2. Nothing that Bedlam uses changed. This is housekeeping, not a fix.
