Bedlam 1.5.3 fixes the connection drops that happen when the screen turns off, and makes the log possible to send.

**The tunnel dropped when the phone slept**

- The phone suspends the CPU soon after the screen turns off. Bedlam's keepalive timer stops with it. The server saw no packets and closed the session after 30 seconds. Neither side told the app.
- Bedlam now checks the tunnel after the device wakes, and after a run of quiet minutes. Before, it only checked when an app was sending data and getting nothing back. A tunnel that died while nothing was using it stayed marked as connected.
- In a test on a frozen client, the old build reported "Connected" for 4 minutes 28 seconds after the tunnel was gone.
- When the wake check finds the tunnel dead, Bedlam now dials again at once. Before, it waited for app traffic or for the next 30-second check.

**QUIC timers**

- The default idle timeout is now 120 seconds and the keepalive is 30 seconds. Version 1.5.2 set them to 30 and 15.
- QUIC uses the shorter of the client limit and the server limit. A 30-second client limit also caps the server, so no server setting could keep a sleeping phone connected for longer.
- **This helps only if you also raise `quic.maxIdleTimeout` on your server.** Against a standard server the limit is still 30 seconds and nothing changes.
- With 120 seconds on both ends, a test client that was frozen for 95 seconds kept its session. It did not have to dial again.

**What this release does not fix**

- Some phones stop Bedlam completely when the screen is off. Xiaomi, Oppo, Vivo and Huawei do this. A stopped app cannot restart itself, and Bedlam cannot fix that in code.
- Turn on always-on VPN in Android settings. The system then starts the service again. This is the only thing that recovers a stopped app.
- Settings, Keep VPN alive lists the other per-phone settings to change.

**The log can now leave the phone**

- The log screen has a Share action. It writes the visible lines to a file and shares it. The file starts with the app version, the phone model and the Android version.
- Long lines now wrap. Before, each line had its own sideways scroll, so a screenshot cut off the end of the message.
- The log keeps 5000 lines instead of 1000, and says so when older lines were dropped.
- The log screen no longer copies the whole list twice per line, and no longer redraws every visible row per line.

**The Session screen showed an address with no tunnel**

- The Session screen ran its address lookup whatever the connection state. With the VPN off it showed your real address, under a caption that said the address came through the tunnel.
- The lookup now needs a live tunnel. With the tunnel down the screen says so. While reconnecting it keeps the last reading and marks it as possibly out of date.

**Fields that showed a bare zero or nothing**

- A numeric profile field left unset showed `0`. You could not tell "unset, the default applies" from "set to zero". Each one now says which it is, and the QUIC timers name their default.
- The MTU field showed an empty box when set to automatic. It now shows the MTU in effect with an `auto` mark.
- Typing an MTU below the 1280 minimum no longer erases what you typed when you tap elsewhere. The text stays and the error stays.

**Other changes**

- The connection timer uses a clock that a time-zone change or a clock correction cannot move. Before, a backwards correction made it count down.
- The connect button stops animating after a few seconds. Before, it animated for as long as a reconnect lasted.
- Settings has an About section with the version, the licence and the source link. Tap the version to copy it.
- The Hysteria core moved from 2.12.0 to 2.12.2. Nothing Bedlam uses changed between them. This is housekeeping, not a fix.
