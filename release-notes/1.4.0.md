Bedlam starts on Android 10 and Android 11 again, protects your saved profiles, and reconnects less often.

**Android 10 and Android 11**

- Bedlam stopped with an error each time you started the VPN. Bedlam now starts correctly.

**Your profiles and settings**

- One damaged profile hid all your other profiles. Bedlam now shows the other profiles.
- New settings in an app update damaged the profiles you saved before. Bedlam now keeps them.
- Bedlam stopped with an error at start after you installed an older version. Bedlam now starts, but it removes your profiles first.
- A failed route refresh deleted the addresses that Bedlam found before. Bedlam now keeps those addresses and shows the error.
- An empty or incorrect custom DNS list stopped all name lookups on the phone. Bedlam now uses Cloudflare DNS instead.

**Connection**

- Bedlam reconnected the tunnel after many connections at the same time, or after an unusual DNS answer. Bedlam now keeps the tunnel open.
- Bedlam showed only "Disconnected" after a failure. Bedlam now shows the reason, for example a wrong password.
- After a failure, you had to close and open the app before you could connect again. You can now connect immediately.
- Bedlam showed "Connected" after it lost the network interface. Bedlam now tries again one time, then stops.
- The "still reconnecting" message stayed in the notification list after the system stopped Bedlam. Bedlam now removes it.
- Bedlam uses less memory in long sessions.

**Hysteria core**

- Bedlam uses Hysteria core 2.12.0.
- The core adds a Chrome fingerprint mode. Bedlam keeps this mode off. The mode stops the connection to a server that uses an Ed25519 certificate, and it gives no protection when you use obfuscation.
- The profile editor has a new switch for the Chrome fingerprint mode, and a new switch for GSO.
