Bedlam shows your saved MTU, uses the standard Hysteria timers, and keeps DNS working on servers that do not deliver UDP.

**The MTU field showed empty**

- The Routing screen read the saved settings after it drew the fields. The MTU field and the custom DNS field thus started empty and stayed empty. Your saved value stayed safe in the database. The screen did not show it. An edit that started from the empty field could erase it. The fields now show the saved values.

**QUIC timers**

- Bedlam now waits 30 seconds before it decides that a silent tunnel is dead. This is the Hysteria server default. Version 1.5.1 set 60 seconds, but QUIC uses the shorter of the client limit and the server limit. Against a standard server, the limit was thus already 30 seconds. Only the log was wrong.
- Bedlam now sends a keepalive packet every 15 seconds. QUIC limits the keepalive interval to half of the idle limit. Version 1.5.1 set 25 seconds, but the tunnel already sent a packet every 15 seconds against a standard server.
- If you raised `quic.maxIdleTimeout` on your server, also set `maxIdleTimeoutSec` and `keepAlivePeriodSec` in the profile editor. The two fields now show their defaults. If the fields are 0, the tunnel uses 30 and 15 seconds.

**DNS stopped on some servers**

- Some servers accept a UDP session but then deliver nothing. Each DNS query then failed with a timeout. The log filled with warnings, and the connection looked dead.
- After three timeouts in a row, Bedlam now sends the next query over TCP. If TCP answers, Bedlam keeps DNS on TCP and writes one warning to the log. DNS over QUIC changes to DNS over TLS. DNS over HTTP/3 changes to DNS over HTTPS.
- Bedlam tries UDP again when the tunnel makes a new connection.
- This applies to the UDP, QUIC, and HTTP/3 transports. The TCP, TLS, and HTTPS transports do not use UDP and did not have this problem.
- This helps DNS only. An app that sends its own UDP traffic through a server that does not relay UDP still gets nothing. The server must relay UDP.

**Lazy mode**

Hysteria's `lazy` option delays the first connection until the first use. Bedlam does not add this option. Bedlam already connects on demand after a drop. The first connection tells you immediately if the profile works.

**Google Play Protect**

Play Protect can still tell you that Bedlam is harmful. The 1.5.1 notes explain the cause and give the signature value of a genuine file.
