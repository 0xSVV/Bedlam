Bedlam 1.5.2 repairs three problems from user reports.

**Settings fields showed empty**

- The MTU field and the DNS servers field now show the saved values. Before, the screen drew the fields before it read the saved settings. The values were safe, but the screen did not show them.

**QUIC timers**

- The default idle timeout is 30 seconds again, the same as the Hysteria server default. The keepalive interval is 15 seconds. QUIC uses the shorter of the client limit and the server limit, so these were already the true values against a standard server.
- If you raised `quic.maxIdleTimeout` on your server, set `maxIdleTimeoutSec` and `keepAlivePeriodSec` in the profile editor. The two fields show their defaults.

**DNS stopped on servers that do not relay UDP**

- Some servers accept a UDP session but deliver nothing. Each DNS query then failed, and the connection looked dead.
- After three timeouts in a row, Bedlam sends the next queries over TCP and writes one warning. DNS over QUIC changes to DNS over TLS. DNS over HTTP/3 changes to DNS over HTTPS. Bedlam tries UDP again when the tunnel makes a new connection.
- This helps DNS only. An app that sends UDP needs a server that relays UDP.
